Multi-Agent Survival Simulation — Why Agents Didn't Talk

The Problem

I wanted to test something more open-ended than a typical project: would LLM-driven agents develop meaningful communication or cooperation on their own, the way OpenAI's hide-and-seek agents discovered tool use without being explicitly programmed for it? I built a real-time survival simulation where autonomous agents, each run by an LLM, had to manage limited resources and could optionally signal to nearby agents. I gave them the capability. I didn't know if they'd use it.

What I Did (and What I Decided)

They mostly didn't. Agents rarely signaled at all, and when they did, the signals carried no consistent meaning and drew no reliable response from other agents. My first instinct was to treat this as a bug — check the code, check the prompt, assume I'd wired something wrong. It wasn't a bug.

I traced it to a structural gap: LLM-driven agents can produce fluent, plausible-sounding text, but fluency isn't the same as a reason to communicate. In OpenAI's hide-and-seek work, cooperative behavior emerged because agents were trained with reinforcement learning — millions of trials where useful behavior was directly rewarded. My agents had no comparable reward signal tied to signaling. Nothing made a "successful" signal more likely to happen again, so communication stayed random and unreinforced.

Alongside this, I also had to solve real infrastructure problems to keep the simulation running at all — a hybrid fallback so agents wouldn't die from LLM latency, graceful degradation for API rate limits, RAG-backed memory to stay inside the context window, and thread-safe locks to prevent race conditions in the physics engine — but the communication result is the one I actually set out to test.

Real log entry from turn 5 of the simulation, translated from the original Turkish for readability. Dusk addresses 'Kael' — an agent not present on the map at this point, a hallucination rather than a signaling bug. Seren and Oryn produce the identical 'foggy mind' fallback thought seconds apart, right after hitting the LLM API rate limit — this is the deterministic fallback mechanism reusing a default low-energy thought instead of generating a fresh one.

What Came Of It

I didn't get emergent communication, and I'm treating that as a real finding, not a failed feature. It's pointing me toward the next version of this simulation: one built on a genetic algorithm instead of LLM calls, where signaling carries a direct energy cost and a direct energy reward — a much smaller feedback loop than an LLM, but a real one, with no dependency on external APIs. The infrastructure work taught me how to keep a live multi-agent system from falling over. The communication result taught me the difference between a system that sounds intelligent and one that's actually under selective pressure to behave that way.
